HOW TO RUN THE PROJECT
----------------------

Requirements:
  - Node.js v18 or higher
  - npm v9 or higher

Steps:
  1. Unzip / navigate into the project folder:
       cd anonboard

  2. Install dependencies:
       npm install

  3. Start the dev server:
       npm run dev
`
  4. Open your browser at:
       http://localhost:5173

  To build for production:
       npm run build
       npm run preview

ARCHITECTURE EXPLANATION
------------------------

The app follows a clean separation of concerns:

  /src
  ├── api/
  │   ├── mockData.js       — In-memory mock data (posts, users)
  │   ├── postService.js    — All post-related data operations
  │   └── authService.js    — All auth-related data operations
  │
  ├── components/
  │   ├── Navbar.jsx        — Top navigation bar
  │   ├── PostCard.jsx      — Individual post card (feed view)
  │   ├── CommentItem.jsx   — Individual comment row
  │   └── Sidebar.jsx       — Right-side sidebar (search, stats, boards)
  │
  ├── context/
  │   ├── AuthContext.jsx   — Global auth state (currentUser)
  │   └── PostsContext.jsx  — Global posts state + sorting
  │
  ├── pages/
  │   ├── FeedPage.jsx      — / route: main post feed
  │   ├── PostDetailPage.jsx — /post/:id route: full thread + comments
  │   ├── CreatePostPage.jsx — /create route: new post form
  │   ├── AuthPage.jsx      — /auth route: login/register/profile
  │   ├── RulesPage.jsx     — /rules route
  │   └── HelpPage.jsx      — /help route
  │
  ├── utils/
  │   └── formatTime.js     — Timestamp formatting utility
  │
  ├── styles/
  │   └── global.css        — E-ink design system & all styles
  │
  ├── App.jsx               — Root component, router setup
  └── main.jsx              — React DOM entry point

UI components NEVER import mockData directly.
All data flows through service functions in /api/.

---------------------------------------------

SERVICE / API LAYER
-------------------

postService.js exposes:
  getPosts()               → returns all posts (async)
  getPostById(id)          → returns a single post with comments
  createPost(data)         → creates and returns a new post
  addComment(postId, data) → appends a comment to a post
  votePost(id, dir)        → up/downvotes a post, returns new count
  voteComment(pid, cid, dir) → votes a comment

authService.js exposes:
  loginUser(credentials)   → validates & returns safe user object
  registerUser(data)       → creates & returns safe new user
  getUserPosts(username)   → returns posts authored by a user

All functions return Promises with simulated 300ms delay,
matching the signature of a real REST API fetch() call.

---------------------------------------------

BACKEND INTEGRATION PLAN
-------------------------

When a real backend is ready, ONLY the /api/ files change.
UI components stay untouched.

Replace mock implementations with fetch():

  // BEFORE (mock)
  export const getPosts = async () => {
    await delay();
    return [...posts];
  };

  // AFTER (real backend)
  export const getPosts = async () => {
    const res = await fetch('/api/posts');
    if (!res.ok) throw new Error('Failed to fetch posts');
    return res.json();
  };

Auth tokens: Add Authorization headers to fetch() calls.
  Store JWT in memory (not localStorage) or httpOnly cookie.

Suggested REST endpoints to implement:
  GET    /api/posts
  GET    /api/posts/:id
  POST   /api/posts
  POST   /api/posts/:id/comments
  PATCH  /api/posts/:id/vote
  POST   /api/auth/login
  POST   /api/auth/register

---------------------------------------------

ASSUMPTIONS
-----------

1. Username uniqueness is validated on the frontend only
   

2. Votes are not de-duplicated per user in this mock —
   backend should implement vote tracking per user... might get scrapped latter on lol 😅😅

3. Passwords are stored in plain text in mockData.js for
   demo purposes only. Backend must hash.

4. No localStorage is used for any core functionality.
   Auth state lives in React Context (in-memory only).
   Refreshing the page logs the user out — expected behavior
   until backend session/token management is added.

5. Images and file uploads are not implemented.
